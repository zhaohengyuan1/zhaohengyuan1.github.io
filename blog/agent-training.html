From a Goal to a Reliable Agent

核心想法
Agent training 是一个反复迭代的过程：定义目标，让模型在环境里做事，判断结果，把经验用于训练，再检查它是否真的变好了。

1. Agent 在学什么？

Agent 用模型决定下一步行动：读文件、调用工具、根据结果继续，直到完成任务。这里的 training 指更新这个决策模型的参数，让它更会完成多步任务。工具、提示词和运行框架也需要配合改进。

想象我们要训练一个会修 bug 的 agent。它需要读报错、找原因、改代码、运行测试，还要在修错方向时回头。我们关心的是整个任务是否完成。

下面是对常见职责的简化拆分。实际团队可能合并阶段、并行推进；其中 rollout、评分和参数更新在 RL 中通常会反复交替。

一个循环，四组工作

  1. 01–04确定学什么目标、评测、环境、任务
  2. 05–08得到学习信号执行、评分、分析、数据
  3. 09–10学习与验证更新模型，检查进步
  4. 11–13交给真实用户整合、发布、收集反馈

2. 先准备目标、题目与环境

先说清“会修 bug”是什么意思，再准备测它的尺子和练习的地方。评测集用于衡量进步，训练任务池用于提供练习；两者服务同一个目标，但要隔离数据。

阶段做什么为什么重要产物
01. 能力定义Capability definition明确要学什么：能定位并修复 bug，且不破坏已有功能。目标越具体，后面的题目、评分和训练才越容易对齐。能力说明
02. 构建评测Eval construction把目标变成可测的题目，写清成功标准，先测旧模型。有起点和尺子，才能知道训练后到底进步了多少。评测集
03. 搭建环境Environment准备可重置的代码仓库、终端和测试工具，记录初始状态。每次从干净环境开始，避免把环境故障或残留文件算成模型表现。运行环境
04. 生成任务Task generation收集真实 bug，补充合成题和边界情况，随能力调整难度与比例。模型学到什么取决于练什么；太简单没增益，太难可能缺少有效反馈。任务池

评测先有可用版本，环境和评分逻辑可以共同完善。保留未用于训练的任务；也要避免把几乎相同的题目分别放进训练集和测试集。

3. 把执行变成学习信号

让模型真正做一遍，才有经验可学。一次修 bug 的轨迹可能是：读报错 → 搜代码 → 修改 → 测试失败 → 再修改 → 测试通过。

阶段做什么为什么重要产物
05. 执行任务Rollout让当前模型实际修 bug，记录观察、动作、工具返回和最终状态。完整执行记录（trajectory）让我们看到它在哪一步做对或走偏。执行轨迹
06. 评分Grading用测试或状态检查验证结果；开放问题可用模型评审，并与人工判断校准。奖励会引导学习。要防止模型靠删测试、改评分等漏洞拿高分。奖励与评分
07. 分析失败Failure analysis读失败轨迹，区分模型错误、任务歧义、环境故障和评分错误。原因不同，修法不同；环境坏了，增加模型训练并不能解决。失败分类
08. 构建数据Data construction整理正确示范、失败后的修正、好坏对比，以及可继续采样的 RL 任务。不同问题需要不同学习信号；原始日志需要筛选、去重和质量检查。训练数据配方
评分要看真实结果。“我修好了”只是模型的说法。应检查 bug 是否消失、原有功能是否正常，并把评分依据放在模型无法篡改的地方。见 Anthropic 的 agent 评测指南。

4. 训练，再验证是否变好

学习方法决定经验怎样进入模型，常见的三种方式是：

  • SFT（监督微调）：模仿高质量示范，学习正确的行动方式。
  • RL（强化学习）：反复尝试，用奖励调整行动选择。
  • 蒸馏：用更强模型的输出或轨迹教目标模型，迁移能力。

它们可以组合，具体取决于数据和反馈；不是每轮都必须全部使用。多步执行如何接入 RL，可参考 Agent Lightning。

阶段做什么为什么重要产物
09. 训练Training选学习方法，更新模型参数，保存模型版本（checkpoint）。把已有示范或反馈转成下一次能用的能力，并检查训练是否稳定。模型版本
10. 评估Evaluation在未参与训练的任务上测新能力、旧能力和安全表现。训练奖励涨了不等于真正变好；还要检查泛化与旧能力退化。评估报告

比较新旧模型时，要使用相同的工具、任务和尝试预算，并通过多次运行观察波动。否则，分数提升可能来自多试了几次，或运行框架变了。

Infra 贯穿全程：环境运行、轨迹采集、评分、模型推理和参数更新要衔接起来。任何一环过慢，都可能让 GPU 等数据；超时与版本记录也会影响训练效率和结果可信度。

5. 整合、发布与下一轮

一个会修 bug 的专项模型，还需要和其他能力一起工作，也需要在实际产品中接受检验。

阶段做什么为什么重要产物
11. 能力整合Integration按需要用混合训练、蒸馏等方式，把不同专项能力整合到候选模型。分别练好的能力放在一起可能互相影响，整合后还要重新评估。候选模型
12. 发布检查Launch gate连同实际工具和运行框架，检查质量、安全、成本与延迟是否达标。模型分数只是系统表现的一部分；用户需要可靠且负担得起的服务。发布决定
13. 线上反馈Production小范围发布或做 A/B 测试，收集用户反馈与实际失败。真实使用会暴露任务池没覆盖的问题，为下一轮训练提供方向。新失败与任务
线上失败 → 定位原因 → 补任务或修环境、评分 → 训练 → 重新评估

例如，模型总在测试失败后停下。先确认测试能正常运行、评分没有误判，再加入“失败后继续定位并修正”的练习。训练后用新的同类任务验证，也检查它是否开始无意义地反复重试。

每轮都要重新检查九件事：目标能力、评测、任务分布、环境、奖励、学习方法、基础设施、能力整合，以及旧能力是否退化。这些决定练什么、怎样学、能否稳定交付。

The core idea
Agent training is an iterative loop: define a goal, let the model act in an environment, judge the outcome, train on the experience, and check whether it improved.

1. What does an agent learn?

An agent uses a model to choose its next action: read a file, call a tool, inspect the result, and continue toward a goal. Here, training means updating that decision model’s parameters to improve multi-step task completion. Tools, prompts, and the runtime also need attention.

Imagine training a bug-fixing agent. It must read errors, find causes, edit code, run tests, and recover when a fix is wrong. We care about whether it completes the whole task.

This is a simplified breakdown of common responsibilities. Teams may combine stages or work in parallel. In RL, rollouts, grading, and parameter updates usually alternate repeatedly.

One loop, four groups of work

  1. 01–04Define the goalCapability, evals, environment, tasks
  2. 05–08Get learning signalsRuns, grades, analysis, data
  3. 09–10Learn and verifyUpdate the model, measure progress
  4. 11–13Serve real usersConsolidate, release, collect feedback

2. Define and prepare

Define what “can fix bugs” means, then prepare the yardstick and practice setting. The eval suite measures progress; the training task pool supplies practice. They share a goal, but their data must be separated.

StageWhat happensWhy it mattersArtifact
01. Capability definitionSpecify the goal: locate and fix a bug while preserving existing behavior.A concrete goal aligns tasks, grading, and training.Capability spec
02. Eval constructionTurn the goal into testable tasks, define success, and measure the current model.A baseline and a clear yardstick make improvement measurable.Eval suite
03. EnvironmentProvide a resettable repository, terminal, and test tools; record the initial state.Clean starts keep infrastructure failures and leftover state from distorting results.Environment
04. Task generationCollect real bugs, add synthetic and edge cases, and adjust difficulty and task proportions.Practice shapes learning. Trivial tasks add little; impossible ones may offer little useful feedback.Task pool

Start with a usable eval; refine the environment and grading together. Reserve held-out tasks, keeping near-duplicates out of both the training and test sets.

3. Turn runs into learning signals

Experience comes from actual attempts. A bug-fixing trajectory might be: read an error → search code → edit → fail tests → revise → pass tests.

StageWhat happensWhy it mattersArtifact
05. RolloutRun the current model on a bug; record observations, actions, tool results, and final state.The trajectory reveals where the agent succeeds or goes off course.Trajectories
06. GradingCheck outcomes with tests or state checks. For open-ended work, calibrate model judges against humans.Rewards guide learning. Guard against shortcuts such as deleting tests or tampering with grading.Rewards
07. Failure analysisRead failed traces; distinguish model errors, ambiguous tasks, infrastructure issues, and grading bugs.Different causes need different fixes. More model training cannot repair a broken environment.Failure taxonomy
08. Data constructionBuild demonstrations, corrections, preference pairs, and RL tasks for further sampling.Different failures need different learning signals. Raw logs need filtering, deduplication, and quality checks.Training mixture
Grade the real outcome.“I fixed it” is a claim. Check that the bug is gone and existing behavior still works. Keep grading evidence beyond the agent’s control. See Anthropic’s guide to agent evaluations.

4. Train and evaluate

Three common ways to turn experience into model behavior:

  • SFT (supervised fine-tuning):imitate high-quality demonstrations of useful actions.
  • RL (reinforcement learning):make repeated attempts and use rewards to adjust action choices.
  • Distillation:teach a target model using a stronger model’s outputs or trajectories.

These can be combined depending on data and feedback; a cycle need not use all three. Agent Lightning illustrates how multi-step execution connects to RL.

StageWhat happensWhy it mattersArtifact
09. TrainingChoose a learning method, update model parameters, and save checkpoints.Turn demonstrations or feedback into reusable behavior while checking training stability.Checkpoints
10. EvaluationMeasure new capabilities, existing capabilities, and safety on held-out tasks.Higher training reward does not establish real progress. Check generalization and regressions.Scorecard

Compare models with the same tools, tasks, and attempt budget, using repeated runs to observe variability. Otherwise, gains may come from more attempts or a changed runtime.

Infrastructure spans the loop:environment execution, tracing, grading, inference, and parameter updates must work together. A slow stage can leave GPUs waiting for data. Timeouts and version tracking affect efficiency and confidence in results.

5. Consolidate, release, repeat

A specialized bug-fixing model must also work alongside other capabilities and survive real product use.

StageWhat happensWhy it mattersArtifact
11. IntegrationWhere needed, consolidate specialized capabilities through mixed training, distillation, or other methods.Individually strong skills can interfere when combined. Evaluate the consolidated model again.Candidate model
12. Launch gateCheck quality, safety, cost, and latency with the actual tools and runtime.Model scores capture only part of system performance. Users need a reliable, affordable service.Release decision
13. ProductionUse staged releases or A/B tests; collect user feedback and real failures.Real usage exposes gaps in the task pool and guides the next training cycle.New failures
Production failures → diagnose → improve tasks, environment, or grading → train → evaluate again

If the agent stops whenever tests fail, first check the tests and grader. Then add practice that requires diagnosing and correcting a failed fix. Verify progress on fresh tasks, and check that it has not learned to retry endlessly.

Revisit nine things each cycle:capability, evals, task distribution, environment, reward, learning method, infrastructure, consolidation, and regressions. Together, they determine what the agent practices, how it learns, and whether it can be delivered reliably.
